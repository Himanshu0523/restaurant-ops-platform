### 🔐 `auth/`
Handles all authentication flows. **Does NOT manage user profile state.**

```
auth/
├── auth.module.ts
├── auth.controller.ts      # POST /auth/register, /login, /refresh, /logout
├── auth.service.ts         # Token generation, hashing, refresh logic
├── auth.guard.ts           # JwtAuthGuard (primary guard)
├── mail.service.ts         # Transactional email (OTP, reset password)
├── constants.ts            # JWT constants
├── decorators/             # @Public() — skip auth guard
├── guards/                 # Additional guards (API key, etc.)
├── schemas/
│   └── refresh-token / OTP schemas
└── dto/
    ├── registerUser.dto.ts
    ├── loginUser.dto.ts
    ├── refreshToken.dto.ts
    ├── forgotPassword.dto.ts
    └── resetPassword.dto.ts
```

**Key flows:**
- `POST /auth/register` → creates `User` doc via `UsersService`, returns tokens
- `POST /auth/login` → verifies password, returns `accessToken` + `refreshToken`
- `POST /auth/refresh` → validates refresh token hash, rotates tokens
- `POST /auth/logout` → clears `refreshTokenHash` on User doc

### 👤 `user/`
Central identity layer. Manages profile, preferences, and role assignment.

```
user/
├── user.module.ts
├── user.controller.ts      # GET /users/me, PATCH /users/profile, etc.
├── user.service.ts         # Core identity CRUD, toSafeUser(), role helpers
├── user.types.ts           # UserRole enum, UserStatus enum, safe user type
├── constants/
│   └── user.constants.ts   # Default values, field limits
├── interfaces/
│   └── user.interface.ts   # IUser interface
├── schemas/
│   └── user.schema.ts      # Mongoose schema (User, UserPreferences sub-doc)
└── dto/
    ├── update-profile.dto.ts
    ├── update-preferences.dto.ts
    └── update-user.dto.ts
```

**Schema highlights:**
- `email`, `password` (hashed), `refreshTokenHash`
- `role: UserRole` — `PLATFORM_ADMIN | OWNER | MANAGER | STAFF | CUSTOMER`
- `status: UserStatus` — `ACTIVE | SUSPENDED | PENDING_VERIFICATION`
- `tenantId?: ObjectId` — null = platform-level user
- `preferences: UserPreferences` — dietary, allergens, language, theme

## 🛠️ Conventions

### File Naming
- **Modules**: `<feature>.module.ts`
- **Controllers**: `<feature>.controller.ts`
- **Services**: `<feature>.service.ts`
- **Schemas**: `<feature>.schema.ts` inside `schemas/`
- **DTOs**: `kebab-case.dto.ts` inside `dto/`
- **Types/Enums**: `<feature>.types.ts`
- **Interfaces**: `<feature>.interface.ts` inside `interfaces/`
- **Constants**: `<feature>.constants.ts` inside `constants/`

### Guard Execution Order
```
Request → JwtAuthGuard → RolesGuard → TenantGuard → Controller
```

### DTO Validation
All incoming request bodies are validated via `class-validator` + `class-transformer` global `ValidationPipe`.

### Error Response Shape
```json
{
  "statusCode": 400,
  "message": "Validation failed",
  "error": "Bad Request",
  "timestamp": "2026-09-21T15:30:00.000Z",
  "path": "/api/v1/users/me"
}
```

## 🔐 Environment Variables

| Variable | Description |
|----------|-------------|
| `MONGODB_URI` | MongoDB connection string |
| `JWT_SECRET` | JWT signing secret |
| `JWT_EXPIRES_IN` | Access token expiry (e.g. `15m`) |
| `JWT_REFRESH_SECRET` | Refresh token secret |
| `JWT_REFRESH_EXPIRES_IN` | Refresh token expiry (e.g. `7d`) |
| `REDIS_HOST` | Redis host |
| `REDIS_PORT` | Redis port |
| `MAIL_HOST` | SMTP host |
| `MAIL_USER` | SMTP username |
| `MAIL_PASS` | SMTP password |
| `PORT` | Server port (default `3000`) |
